**The lesson first, because it is the durable part.** The navbar work earlier this session was reported as done on the strength of a clean build, a clean typecheck, and per-route greps over the built HTML confirming which chrome each page carried. All of that was true and the page was still visibly broken. `AGENTS.md` now carries a "Verifying a UI change" section: build, `npm run serve`, screenshot with a real browser at a real viewport, and measure in the page before touching CSS.

Two tooling notes that cost time and are worth not rediscovering:

- `npm start` renders client-side, so its HTML is an empty shell. Screenshots have to come from `npm run serve` over a production build.
- `chrome --headless --screenshot --window-size=390,760` is not a 390px CSS viewport. It reported the home page heading as clipped and the burger as missing; both were false. `puppeteer-core` with `page.setViewport`, pointed at the installed Chrome, gives an honest render. Installed in the scratchpad, never as a dependency of this repo.

---

**Bug 1, and the worst of the three: Bulma silently overrode the site's `breakpoint()` mixin.** Bulma 0.9 defines `=breakpoint($name)` in `sass/utilities/mixins.sass`. The port imports Bulma first and every partial after it, all inside one `.marketing` block, so Bulma's definition won for all **216** `@include breakpoint(...)` call sites across all nine pages. Bulma's version looks the name up in a `$breakpoints` map and emits nothing at all on a miss, with no warning. Every responsive rule in the marketing styles compiled to nothing.

The Gatsby build never hit this because each component stylesheet re-imported `variables` itself, which is exactly the structure the port collapsed. Fixed by re-importing `variables` after Bulma inside the block, with a comment saying why it has to stay there. Confirmed by compiling the stylesheet directly and counting the emitted media queries: zero before, five `min-width: 1160px` and six `max-width: 767px` after.

**Bug 2: Infima's global `.navbar` rule reached the marketing navbar.** It pins the element to `--ifm-navbar-height` and adds its own padding, so the navbar was crushed to one 64px row with the menu spilling over the hero, which is what the review screenshot showed. Overridden in `_navbar.scss` at a specificity that beats it. Infima's other navbar classes are BEM (`.navbar__brand`), so `.navbar` is the only collision there.

**Bug 3: every button lost its padding**, from the same restructure. `.custom-button { padding: 0 }` used to lose to Bulma's `.button` padding, because webpack put the component stylesheets before Bulma and equal specificity meant last-one-wins. In a single stylesheet the order reversed. Dropped the line; `.custom-button.default` still sets its own padding, so that variant is unchanged.

**One thing that was ugly rather than broken.** The three new products sections used icons picked by name from the general icon set, which range from 36x36 to 196x202. The `product*` family the existing sections use is drawn to a single 112x112 viewBox, which is why the original page never had to specify a size. Rendered a contact sheet of the 15 matched icons and picked from those by looking at the glyphs. Only three of the fifteen were unused, so the new sections reuse icons the older ones already carry; that is noted as an open question alongside their missing section artwork. `_yellowbutton.scss` now pins the icon size so an outside-the-set icon cannot break the row again.

**Corrected a framing error in `ia-proposal.md` (2026-08-07).** The first revision read the RSMF LOI and carried its emphasis across without questioning it, making sovereignty one of three headline pillars.
