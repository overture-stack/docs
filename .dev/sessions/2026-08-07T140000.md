## What landed

**Bulma removed, replaced by `src/marketing/styles/_layout.scss`.**

Method mattered here, so it is worth recording. Rather than reading Bulma and reimplementing it, Bulma was compiled with this site's own variable overrides, then a script extracted every rule whose selector could match the marketing markup and discarded the rest. The complete Bulma vocabulary the nine routes use turned out to be 21 class names, so the reachable surface was about 100 rules out of 291KB compiled. `_layout.scss` is those rules with Bulma's values verbatim.

- `bulma` uninstalled. Gone with it: the `$navbar-breakpoint`/`$navbar-item-*`/`$link`/`$primary-invert`/`$family-*` overrides, `@import "bulma/sass/utilities/initial-variables"`, the second nested `@import "variables"` that existed only because Bulma clobbered the site's `breakpoint()` mixin, and the `includePaths`/`quietDeps` Sass options.
- Verified before removing the variables import: nothing in the tree used a variable only Bulma defined.
- Stylesheet: **561,118 to 362,229 bytes raw, 96,666 to 70,922 gzipped**. Every documentation page loads that file too.

**Prefixed Tailwind v4 added.** `src/css/tailwind.css`, wired through a `configurePostCss` plugin and the `customCss` array. `prefix(ow)`, preflight left out by importing the `theme` and `utilities` layers individually, `source(none)` plus explicit `@source` so it does not crawl `submodules/` and `website-legacy/`.

**Privacy and terms are Markdown.** 476 lines of JSX became 39 lines of route shell plus 145 lines of prose in `src/marketing/content/`. `ProsePage.tsx` is the shared hero-and-article wrapper.

## Three things measurement caught that reading would not have

**1. "Seven class families" undercounted Bulma badly.** It also supplied the element reset the marketing pages sit on: `margin: 0` on every heading, paragraph and list, `h1`-`h6` at `font-size: 100%`, `ul { list-style: none }`, `box-sizing: inherit`, `img { max-width: 100% }`. Dropping that would have handed all nine routes to Infima's typography at once. `_layout.scss` is 624 lines rather than the ~120 the class families needed. Found by extracting element and universal selectors separately from the class ones, on the suspicion that a reset was hiding in there.

Related: the marketing box model was resolving `box-sizing: inherit` up to a global `*` rule that arrives with **swagger-ui's** stylesheet. `_base.scss` now states `border-box` on `.marketing` itself. Same computed value, one less accident.

**2. basscss has been dead since stage 1.** `_util.scss` opened with "Custom utility classes for when basscss doesn't do the trick", and basscss is a dependency of the Gatsby site, not this one. So all 41 uses of `bold`, `mt1`, `mt2`, `mt3`, `ml2`, `mr2`, `mx2`, `my2`, `pt2`, `pb3`, `pr1`, `pr2`, `px1`, `px2`, `py2`, `py3` across the marketing pages resolved to nothing, and had since the port. The four that appeared to resolve were `.swagger-ui .pt2` and friends, scoped away from these pages.

Replaced with `ow:` equivalents at basscss's real values, read out of the package rather than guessed: scale 1 = .5rem, 2 = 1rem, 3 = 2rem, 4 = 4rem, so basscss N maps to Tailwind 2N. `bold` is 700.

Both `typecheck` and `build` were green through all of this, because a class name is a string. There is a roadmap entry for the check that would have caught it.

**3. Tailwind utilities needed `!important`, and finding out required measuring each one.** With utilities in `@layer utilities` and the marketing SCSS unlayered and nested under `.marketing`, the SCSS outranks a bare utility twice: unlayered beats layered whatever the specificity, and `.marketing h1` carries one more class than `.ow\:py-8`. 6 of 17 combinations silently lost, including `ow:py-8` on the privacy `h1` computing to 0px and `ow:font-bold` computing to 900 because `_layout.scss`'s `span { font-weight: inherit }` beat it.

Layering the marketing SCSS beneath utilities is not available: it would then lose to Infima, which is unlayered. So `important` on the utilities import. After: 17 of 17, zero overridden. Mitchell chose this over fixing the six cases individually in SCSS, on the grounds that phase 3 hits the same wall constantly.

## Prose conversion notes

Docusaurus routes `.mdx` in `src/pages/`, and it was the wrong tool. `MDXPage` wraps content in Infima's `container container--fluid` plus a row/col grid and a table of contents, and puts `wrapperClassName` on `<html>` rather than the content wrapper. So the route stayed `.tsx` and imports the Markdown as a component; the Markdown lives outside `src/pages/` because anything under there becomes a route.

The prose was extracted from the built HTML by script rather than retyped, which is why the rendered text of both pages diffs clean against the JSX version. Retyping two legal pages by hand was the obvious way to introduce a content bug.

Two judgement calls inside it:

- Bullets are loose lists in the Markdown (blank line between items) because the items run long and that is much easier to read. Loose items arrive wrapped in `p` and picked up the 20px paragraph margin, spacing the bullets apart. Zeroed `ul li > p` instead of tightening the source.
- The terms section numbers were briefly a CSS counter, which auto-renumbers and is tempting. Reverted to real text in the Markdown: generated content cannot be selected or copied, and these get cited by number. Costs manual renumbering if sections move; noted in the file.

## Verification

`baseline-stage2/` was the wrong comparison for this phase, since the claim under test was that removing Bulma changes nothing. So the pre-phase-2 build was kept and served alongside the new one on a second port, and both were captured.

- **Bulma removal: all 33 captures byte-identical** (nine routes at 390/900/1440, plus `/deploy/` and `/community/citing-us/`). Page heights matched to the pixel.
- **Mobile menu measured, not eyeballed:** closed `display: none`, open `display: flex` at 848px, burger spans to opacity 0 and ±45deg, desktop navbar 65px with the burger hidden. Identical across both builds.
- **Documentation pages byte-identical at every step**, including after the `!important` change. This was the thing most likely to break and was checked each time.
- **Prose pages:** rendered text diffs identical to the JSX version on both. Terms differs visually only in the 8 heading rows, where the number now has a space before the title so it copies as "1 Terms & Conditions" rather than "1Terms". Privacy differs only in the address block, now one paragraph with line breaks instead of six divs, 20px taller.
- No horizontal overflow at any route or viewport. `typecheck` and `build` green.

Captures in `.dev/after-phase2/`.

Roadmap entry added.
- **The Sass `@import` deadline.** Phase 2 was supposed to retire it and did not; the roadmap's reasoning assumed almost no SCSS would remain, and 2,800 lines remain, still needing `.marketing { @import ... }`. Corrected in the roadmap with three candidate answers. Nothing is blocked on it.
