- `src/marketing/components/HomeCollaborate.tsx`, `src/marketing/styles/pages/_home.scss`: the band's opening was a `.t-p1` lede (24px at desktop) over two 17px notes, three sizes telling one statement about the team. All three paragraphs are `&__prose` now at 1rem, and `&__values` and `&__selfServe` came down from 1.0625rem to match, so the band is one voice throughout. `P1` has no reader left in this file.
- The floor is 1rem, not lower, and the reasoning is in the stylesheet rather than here: WCAG sets no minimum font size, so what bounds it is 16px as the browser default and the accepted floor for body copy, `rem` rather than `px` so a user's own text size carries (1.4.4), and a 1.6 line height above the 1.5 a user must be able to set (1.4.12). Contrast is not the constraint: `$navy-black` on this band's `$grey-2` is 12.17:1 against the 4.5:1 normal-size text must clear. Dropping under 24px does leave WCAG's "large text" bracket, where 3:1 would have been enough, but no size in play here fails at 12.17:1.
- `src/marketing/styles/pages/_home.scss`: the paragraph gap is 1.5rem, and it is written `&__prose + .HomeCollaborate__prose`. A paragraph gap has to beat the gap between two lines inside a paragraph or it is not a break, and 1.6 on 16px type puts 25.6px between lines, so the 1rem the notes used to carry was less than a line gap. The first attempt at the rule was `&__prose + &__prose`, which compiles to `.HomePage .HomeCollaborate__prose + .HomePage .HomeCollaborate__prose` — a descendant of `.HomePage` following a sibling, which matches nothing. It failed silently and the three paragraphs rendered with no gap at all; caught by measuring the rects, not by reading the file.
