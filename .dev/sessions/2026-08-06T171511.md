**Stage 1: the port.** `website/src/marketing/` holds the components, constants, case-study data and the Sass tree; `website/src/pages/<route>/index.tsx` holds one file per route. Nine routes build: home, about-us, acknowledgements, case-studies, getting-started, privacy, products, services, terms-conditions. 390 pages total, `onBrokenLinks: "throw"`, and `npm run typecheck` clean.

**Two routes went differently from the plan, both surfaced rather than absorbed:**

- **The marketing home is at `/home/`, not `/`.** `/` is the documentation homepage in this build (`src/pages/index.tsx`). Stage 1's own constraint is that nothing a visitor sees changes, and stage 3 is where the marketing build gets its own root, so taking `/` now would have broken both rules at once
- **`community` is not ported.** It rendered only a title and a keywords meta tag, its stylesheet was empty, and `/community` is already the `routeBasePath` of the community documentation plugin instance, so the route would have collided outright. Recorded as an open question rather than quietly dropped

**Three more components were dead by the roadmap's own test.** `Content`, `ImageCrossfade` and `Badge` are on the port-as-is list but have no importers anywhere in the ported site; `CaseStudy` imported `ImageCrossfade` and never rendered it. Applied the same "do not port the dead components" rule uniformly instead of porting three files nothing calls. Unreferenced case-study assets went too, taking `static/img/marketing/` from 6.3MB to 2.6MB.

**Scoping the styles is the part worth checking.** `marketing/styles/index.scss` imports every partial inside `.marketing`; `MarketingPage.tsx` puts that class on Docusaurus's content wrapper via `wrapperClassName`, so it covers the page content and not the navbar or footer. Verified against the built CSS rather than assumed: Bulma's `.columns` only ever appears as `.marketing .columns`, and its `html`/`body` resets compile to `.marketing html` / `.marketing body`, which never match. That last part is the catch, so `_base.scss` re-applies what those rules set to `.marketing` itself. Variables and mixins stay at the top level, because Sass scopes a variable to its block.

**Deliberate library choices:**

- **Bulma held at 0.9.4.** 1.x is a rewrite that would not take the variable overrides the marketing styles set
- **`quietDeps` plus `silenceDeprecations: ["import"]`.** Bulma 0.9 uses Sass features Dart Sass has deprecated; `quietDeps` covers those without hiding ours. The `@import` one is genuinely ours: `@use` cannot be nested inside a selector, so the scoping strategy has no modern equivalent. Checked that no marketing partial uses `darken()`, `lighten()`, `unit()` or the global `if()`, so nothing of ours is being hidden. Build output went from 43 warnings to 1
- **`react-modal`, `react-waypoint`, nprogress and `proper-url-join` all dropped.** The first was imported by the home page but never rendered; the second only fed the case-studies scroll tracking, now an `IntersectionObserver` effect, which avoids a stale dependency in exactly the place Docusaurus SSR is fussiest

**`npm run typecheck` fixed, which the roadmap had on the critical path.** The `"ignoreDeprecations": "6.0"` was silencing an editor-only warning about `baseUrl` (set by `@docusaurus/tsconfig`, dropped in TypeScript 7), and the installed TypeScript rejects that value, so the repo had traded its only type gate for a quiet editor. `baseUrl: "."` is genuinely needed, since the base config's resolves inside `node_modules` and breaks every `@site/*` import; it is back, with a comment saying not to add the suppression again. Four pre-existing `JSX.Element` errors came with it: `@types/react` 19 removed the global `JSX` namespace, so they are `React.JSX.Element` now. The port is written in `.tsx` with typed props for the same reason: the gate works, so new code should be under it.

**Accessibility fixes, since the content was moving anyway.** `Icon` requires `alt` rather than defaulting it, so decorative use has to be deliberate; every `<img>` on all nine built pages carries one, checked against the built HTML. `Button` gained `ariaLabel` for the icon-only carousel arrows. The two clickable-`<img>` controls (the home logo strip, the case-studies logo nav) are wrapped in real `<button>`s. The floating cubes on the home page lost their descriptive alt text in favour of `alt=""`, which is what they are.

**Small correctness fixes made in passing, all inert-but-wrong in the original:** `` `${isProductPage && 'class'}` `` rendered the literal string `false` into `className` on `YellowButton` and two sections; `ServicesPageSection` nested a `<ul>` inside a `<p>`; the case-studies page carried per-case screenshot state and two handlers that nothing ever called, since every case study has exactly one screenshot.

**`ProductsPageSection` changed shape.** Nine flat `yellowButton*` props became a `features` array. That is more than a translation, and it is what made writing three more sections tolerable.

**Products page copy is a draft.** Lectern, Lyric and Stage are written from each component's own overview under `website/docs/develop-docs/`, so the content is accurate rather than invented, but it has not been through whoever owns that page. Lectern and Lyric have no section artwork and nothing in the Gatsby assets fits, so `src` is optional now and those two render without it. Both left as open questions.

**Flagged, not fixed:** the home and getting-started pages still tell users to `git clone -b quickstart .../prelude.git`, and the docs site retired that page on 2026-07-30. Ported verbatim because it is content, not translation; `PRELUDE_DOCS_LINK` is already in the constants for whoever rewrites it.

**One warning left in the build, and it is a false positive.** Docusaurus reports the six `/home/` anchor links as broken; all six ids are in the built HTML. Its anchor checker only collects ids from Markdown headings, not JSX pages. Left `onBrokenAnchors` at `warn` rather than `ignore`, because ignoring it globally would mask real breakage across the documentation, which is much the larger surface.
