## Two things found by measuring

**Responsive utilities were broken in production builds, and had been since phase 2.** `ow:lg:flex-row` lost to `ow:flex-col` at 1440px. Chased it properly rather than working around it:

1. Both classes exist in the built CSS, and the `lg` rule is later in the file, so it should win.
2. It is in a `@media (min-width:64rem)` block at byte 354353. The `@layer utilities` block runs 62509 to 65343. The variant is outside the layer its base utility is inside.
3. Docusaurus's production CSS minifier merges every `@media` block and moves the result to the end of the stylesheet, which is what lifts it out. Built with `--no-minify` to confirm: both rules stay in the layer, the variant works.
4. Layered and unlayered `!important` declarations do not rank by source order, layered wins, so the hoisted variant could never win.

Fixed by dropping `layer(utilities)` from the import in `src/css/tailwind.css`. Both rules are then unlayered and important, so Tailwind's ordering decides again. The layer was not doing anything else: utilities need `important` to beat `.marketing X` either way. Nine marketing routes and two documentation pages captured before and after: byte-identical, except one docs page that also differs from itself between two runs of the same build, nine pixels of font antialiasing.

**Bare elements on marketing pages do not inherit the brand font.** Bulma set `font-family` on `body`; when the styles were nested under `.marketing` in the port that rule had nowhere to land, and `_base.scss` re-applied Bulma's `html`/`body` values without it. Everything ported takes the family from its `.t-*` class, so nothing showed it, which is why phase 2's byte-identical captures did not catch it. New markup has to state it, as the prose pages already do. Stated once in `_products.scss` rather than changing the `.marketing` wrapper, which would touch nine routes for no visible gain.
